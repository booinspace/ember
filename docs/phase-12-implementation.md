# Phase 12 — shared skills and harness capabilities

## Delivery scope and ownership

One operator-visible catalog joins native/MCP/public tools with skills reported by
the selected harness. The shared portable package repository is operational data,
not a third product or a second copy of a framework. Hermes owns parsing/loading
and procedural execution through an explicitly installed adapter. Ember owns the
neutral contracts, grants, current enablement checks, task/gateway admission,
receipts and dashboard. A future OpenClaw adapter implements the same skill-provider
contract; no OpenClaw runtime is installed in this phase.

The selected adapter reports bundled, optional and shared packages, with stable
source identity, complete package/document hashes, original provider metadata,
resources and translation diagnostics. Operator enable/disable uses compare-and-set
state. Imported packages round-trip original bytes/metadata. Duplicate names require
an exact package identity. Resources reject traversal, absolute/Windows paths,
symlinks and case collisions; text loads are bounded and never executed.

Metadata is listed first. Only up to eight enabled/compatible skill descriptions
enter conversational delegation, and only selected complete instructions/resources
enter a task. The native Hermes read path disables preprocessing; dependency installers,
credential capture, shell, independent memory and automatic skill learning are not
exposed. Missing requirements/oversized procedures are explicit unavailable outcomes.
The 16 KiB P2 and 24 KiB conversational guards remain unchanged.

A bounded public-page reader supplies the requested URL-summary use case. Literal
user URLs can be read before one foreground CharacterCore reply; delegated Hermes
reads go through the same broker. Private context cannot drive public requests.
HTTP(S), public resolved addresses, pinned connections, redirects, wire/time/content
limits and cited partial coverage are enforced. No browser/login/PDF execution or
paid/cloud extraction fallback is added.

## Scope map

- Neutral skill contracts/provider client; installed Hermes adapter and sealed assets.
- Harness startup, tool/skill catalog, task dispatch and result/current-authority checks.
- Core's bounded delegation descriptions and literal public-page preflight.
- Authenticated skills list/view/enable/import/export endpoints and dashboard panel.
- Shared example packages, SDK/transport/budget/revocation/portable-resource regressions.
- PLAN, root/component ADRs, runbook, sanitized acceptance/latency evidence.

## Acceptance and failures

P12-AC-01/02: real native parser/loader, raw metadata/resource round-trip, duplicate,
version/path/resource failures and OpenClaw extensions without its runtime.
P12-AC-03: metadata-first list; actual SDK selected skill/resource loading; no whole
catalog in prompts; unchanged final serialization guard.
P12-AC-04/05: current grants/enablement, no installer/preprocessor/effect escalation,
whole mandatory procedures or explicit unavailable; stale copies/results suppressed.
P12-AC-06: offline packages, malformed/malicious resources, provider missing/disabled,
actual Hermes/gateway task, link summary, dashboard and unchanged ordinary chat/recall.

Discovery failures leave native chat, memory and direct tools usable. Startup never
installs/downloads or silently reseals code. P2 still waits for realtime reservations;
physical model abort and scheduling remain Phase 13. Desktop remains independent.
